# Codex 与 OpenClaw 使用约定

## Codex

- 在 Codex 中打开仓库后，以根目录 `AGENTS.md` 为持久项目规则。
- `.codex/config.toml` 提供本仓库的默认安全边界：工作区写入、敏感操作按需确认、日常中等推理强度。个人或组织策略可以更严格。
- 建议个人默认：工作区写入权限、安装依赖/联网/删除/Git 推送需确认、日常中等推理强度。
- 不将个人 Codex 全局配置、认证信息或连接器密钥提交到仓库。
- 日常最多并行 3 个子 agent；只对边界清晰的任务并行，并由主 agent 集成共享文件。

## OpenClaw

- OpenClaw 与 Codex 可以交替使用，但不得同时写入同一工作区。
- 首次交接给 OpenClaw 时，要求其先读 `CONTEXT.md`、`docs/当前状态.md`、`docs/交接记录.md`。
- 默认将 OpenClaw 用于任务提醒、状态汇总和只读检查；如需写代码，使用独立分支或 worktree。
- 不授予自动推送、部署、删除、读取 `.env` 或操作真实 CAD 资产的权限。

## 跨设备交接

1. 完成相关测试或如实记录未验证项；
2. 更新当前状态和交接记录；
3. 提交到 Git 分支并推送；
4. 在另一台设备/工具拉取同一分支；
5. 先阅读上述三个上下文文件，再继续工作。
