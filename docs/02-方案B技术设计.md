# 02-方案B技术设计：SW 原生 SLDDRW 改造

**日期**: 2026-08-02 · **状态**: 待老板审批 · **取代**: 01-方案中 DXF 载体路线（Step3/4/5/7 渲染层）

---

## 1. 背景与立项依据

2026-08-02 老板目视验收 M2 产物 drawing.dxf，判定 **DXF 线稿路线不满足交付形态**：

- DXF 全部实体在模型空间，SW 打开后图纸页为空（结构性短板，非 bug）
- 视图是死线、无 3D 关联；标注是"三线+文字"假标注，非 SW 标注对象、不可驱动
- BOM 是自绘表格线，非原生 BOM、无序号球标
- 对比基准：`LB26拉臂装置/LB26.00000拉臂总成.DWG`（完成图纸）；同目录 SLDDRW 为空白模板（spike 实证），仅用于提取图框/标题栏格式

**教训（已入 MEMORY）**：方案审查的基线必须是用户可验收的真实样例（LB26 案例图），不是内部设计文档。每里程碑验收第一项 = 目视对比案例图纸。

**目标不变（2026-08-01 老板定调）**：给 3D 模型 → 输出生产工程图，减少工作量。AI 做能做的，做不到的留给人补。人机协同是设计目标。

## 2. 总体架构

```
SW模型 ──▶ Step1 加载 ──▶ Step2 解析 ──▶ Step3 建图纸+插视图 ──▶ Step7 骨架收尾
                                                            │
                                      Step5 原生BOM+球标  │  Step6 技术要求
                                      Step4 标注（规则筛+AI筛） │
                                                            ▼
                                          SLDDRW ──SaveAs──▶ DWG / PDF
```

**五阶段映射**（前端阶段产物页分组）：
- 导入 = Step1, 2（模型加载、几何解析）
- 骨架 = Step3, 7（视图投影、图纸收尾）
- 表格 = Step5, 6（BOM生成、技术要求）
- 标注 = Step4（尺寸标注）
- 审查 = Step8（审查闭环）

**每步留痕**：`preview.png`（真图快照）+ `result.json`（结构化数据）+ **该步版本 SLDDRW 副本**（`step7_skeleton.slddrw` / `step5_table.slddrw` / `step6_table.slddrw` / `step4_final.slddrw`）。

**角色分工**：规则引擎 = 骨架（稳定可测）；SW = 绘图员（画一切）；AI = 总工+质检（判断）；人 = 终审。

**AI 双职责（本期落地，非二期）**：
1. **Step4 尺寸筛选决策**：709 个模型尺寸 → AI 判断哪些放/哪些不放（多模态：看视图快照+读结构数据）
2. **每步末尾 AI 质检**：看真图快照+结构化数据 → 判定"自动放行"或"暂停待人工"

## 3.x 视图策略与数据模型（B-M1+ 扩展）

Step3 的视图布局引擎由静态配置升级为**策略驱动的数据模型**，支撑多类型视图混合排布与用户覆盖干预。

### ViewType 枚举

| 枚举值 | 含义 | 典型用途 |
|--------|------|----------|
| `STANDARD` | 标准投影视图 | 主视、俯视、左视、右视、后视、仰视 |
| `ISOMETRIC` | 轴测图 | 装配体整体外观、焊接件空间关系表达 |
| `DETAIL` | 局部放大图 | 复杂特征（焊缝、螺纹、小孔）的局部放大 |
| `SECTION` | 剖视图 | 内部结构表达，依赖 `cut_line` 定义剖切线 |
| `AUXILIARY` | 辅助视图 | 倾斜面真实形状表达，依附于 `parent_id` 视图 |

### ViewConfig 扩展字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `str` | 视图唯一标识（策略内自洽，如 `"front"`、`"detail_a"`） |
| `view_type` | `ViewType` | 视图类型，决定 COM 调用路径与布局规则 |
| `parent_id` | `str \| None` | 父视图 ID；DETAIL / AUXILIARY / SECTION 必须指向一个 STANDARD 视图 |
| `scale` | `float \| None` | 显式比例；`None` 时由布局引擎按“填满可用区”自动试算 |
| `position_mode` | `str` | 定位模式：`"auto"`（约束布局）、`"hint"`（用户提示）、`"absolute"`（绝对坐标，人工干预） |
| `position_params` | `Dict` | 模式参数：如 `{"relation": "below", "ref": "front"}` 或绝对 `(x, y)` |
| `region` | `Dict \| None` | DETAIL 专用：局部放大区域，格式 `{center: (x,y,z), radius: float}` |
| `cut_line` | `List[Tuple] \| None` | SECTION 专用：剖切线 polyline（模型空间坐标），驱动 `CreateSectionViewAt5` |

### 用户覆盖机制

前端在生成请求中可通过 `GenerateRequest` 传入以下覆盖字段，干预 Step3 布局结果：

| 覆盖字段 | 作用域 | 示例 |
|----------|--------|------|
| `part_type_override` | 类型识别 | 强制按 `"焊接件"` 走对应默认视图建议 |
| `views_override` | 视图列表 | 增删视图、修改 `view_type` / `scale` / `position_mode` |
| `layout_mode` | 全局策略 | `"auto"`（约束布局自动填充）/ `"manual"`（用户辅助指定位置） |
| `positions_override` | 绝对定位 | 对指定 `id` 的视图强制写入 `(x, y)`，绕过约束布局 |

### apply_overrides 合并逻辑

```
BaseStrategy（类型识别默认输出）
  + suggested_views（type_recognition.py 按零件类型推荐的默认视图列表）
  ──▶ apply_overrides(strategy, overrides)
       ├─ views_override：按 id 匹配 → 字段级 patch / 新增 id 追加 / 显式 null 删除
       ├─ layout_mode：替换 strategy.layout_mode
       ├─ positions_override：写入对应 view.position_mode="absolute" + position_params
       └─ projection_type：仅在用户显式传值时覆盖，否则保持默认值
       ──▶ FinalStrategy → to_layout_input() → 布局引擎
```

**向后兼容**：`get_view_strategy()` / `create_view_strategy_result()` / `to_layout_input()` 接口签名不变；旧调用方不传 `overrides` 时行为与改造前完全一致。

### 多比例并存

- 主比例：由布局引擎按"填满可用区"自动试算（如 1:50）。
- 辅助比例：用户显式指定或默认取主比例的 2x 放大（分母减半，如 1:25）；`DETAIL` / `SECTION` 视图独立设置 `scale`。
- 单张图纸允许多个视图以不同比例并存，布局引擎按各视图缩放后尺寸计算占用空间。

### 第一角投影（GB标准）

- `projection_type` 默认 `"first_angle"`（中国国标 GB/T 14692），即物体处于观察者与投影面之间。
- 可选项 `"third_angle"`（第三角投影，常用美标），供出口图纸切换。
- 该字段仅影响 `STANDARD` 视图的默认方位命名与布局提示，不改变 COM 投影数学（SW API 内部已处理）。

## 4. AI 质检守门员机制（核心新增）

每步执行完 → **留痕三件套** → AI 质检 → 三态判定：

```
Step N 完成
  ├─ 留存：output/step_N/preview.png（SW 真图快照）
  │        output/step_N/result.json（结构化数据，现成）
  │        output/step_N/step{N}_xxx.slddrw（该步版本 SLDDRW 副本）
  ▼
AI 质检（多模态：preview.png + result.json + 该步版本 SLDDRW + 该步规则红线）
  ├─ PASS：自动放行 → Step N+1（批量任务全程无感）
  └─ NEED_HUMAN：暂停流水线，前端弹处理卡片
       （问题描述 + 真图快照 + 待处理清单 + 操作建议）
       人处理完点"继续" → 局部重跑该步或放行
```

**AI 质检规则示例**：
- Step3：视图是否都在图幅内？比例是否离谱？有无视图重叠？
- Step4：标注密度是否超标？清单项数是否异常（>阈值提示人工决策）？
- Step5：BOM 表是否超图幅？行数与组件数是否一致？
- 红线类（检查点损坏、COM 失败）不走 AI，直接按现有异常体系报错。

**成本**：每步 1 次多模态调用，单图全流程 ≤10 次，成本几分钱级。

## 5.x 检查点重跑与用户辅助（B-M1+ 扩展）

用户在任意步骤被 AI 拦截或事后想调整参数时，无需从头跑整条流水线，支持**从指定检查点局部重跑**。

### 检查点重跑机制

- **接口**：`POST /api/generate/{task_id}/rerun`
- **请求体**：`RerunRequest`
  - `from_step`：`"step3"` / `"step4"` / `"step5"` / `"step6"` / `"step7"`，标识从哪一步开始重新执行
  - `overrides`：与 `GenerateRequest` 同结构的覆盖参数，仅对 `from_step` 及后续步骤生效
- **行为**：
  1. 后端加载该 `task_id` 已持久化的 `step{N-1}` 版本 SLDDRW 作为起点（如 `from_step="step5"` 则加载 `step4_final.slddrw`）
  2. 将 `overrides` 合并到该步骤的输入策略 / 请求模型
  3. 从 `from_step` 顺序执行至流水线终点，每步重新走 AI 质检
  4. 旧 `from_step` 及之后的产物文件被覆盖，之前的步骤产物保留不变

### Step6 / Step7 参数覆盖

| 步骤 | 可覆盖内容 | 典型场景 |
|------|------------|----------|
| Step6 | 标题栏属性（`title_block_fields`：图号、名称、材料、重量、比例、设计/审核/日期等） | 用户发现标题栏属性链接错误，批量修正 |
| Step6 | 技术要求文本（`tech_notes`：模板条目勾选/排序/自定义追加） | 特定客户需要额外热处理要求 |
| Step7 | 图纸格式切换（`sheet_format`：A4 → A3 自动升级，或强制指定） | 视图排布后图幅不足，人工指定大图 |

### 前端参数面板交互

1. **触发时机**：AI 质检 NEED_HUMAN 弹出的处理卡片中，提供「调整参数并重跑」按钮；终图页也常驻「参数微调」入口。
2. **面板形态**：按步骤分组的可折叠表单（Step3 视图配置 / Step6 标题栏 / Step6 技术要求 / Step7 图纸格式）。
3. **草稿态**：用户的覆盖修改先存前端草稿，点击「预览重跑」才发请求；后端返回新预览图后，用户可对比新旧快照，确认再覆盖。
4. **撤销**：每次重跑生成新的产物版本号（`step3_v2.slddrw`），支持回退到上一版本。
