# 02-方案B技术设计：SW 原生 SLDDRW 改造

**日期**: 2026-08-02 · **状态**: 待老板审批 · **取代**: 01-方案中 DXF 载体路线（Step3/4/5/7 渲染层）

---

## 1. 背景与立项依据

2026-08-02 老板目视验收 M2 产物 drawing.dxf，判定 **DXF 线稿路线不满足交付形态**：

- DXF 全部实体在模型空间，SW 打开后图纸页为空（结构性短板，非 bug）
- 视图是死线、无 3D 关联；标注是"三线+文字"假标注，非 SW 标注对象、不可驱动
- BOM 是自绘表格线，非原生 BOM、无序号球标
- 对比基准：`LB26拉臂装置/LB26.00000拉臂总成.DWG`（完成图纸）；同目录 SLDDRW 为空白模板（spike 实证），仅用于提取图框/标题栏格式

**教训（已入 MEMORY）**：方案审查的基线必须是用户可验收的真实样例（LB26 案例图），不是内部设计文档。每里程碑验收第一项 = 目视对比案例图纸。

**目标不变（2026-08-01 老板定调）**：给 3D 模型 → 输出生产工程图，减少工作量。AI 做能做的，做不到的留给人补。人机协同是设计目标。

## 2. 总体架构

```
SW模型 ──▶ Step1 加载 ──▶ Step2 解析 ──▶ Step3 建图纸+插视图 ──▶ Step7 骨架收尾
                                                            │
                                      Step5 原生BOM+球标  │  Step6 技术要求
                                      Step4 标注（规则筛+AI筛） │
                                                            ▼
                                          SLDDRW ──SaveAs──▶ DWG / PDF
```

**五阶段映射**（前端阶段产物页分组）：
- 导入 = Step1, 2（模型加载、几何解析）
- 骨架 = Step3, 7（视图投影、图纸收尾）
- 表格 = Step5, 6（BOM生成、技术要求）
- 标注 = Step4（尺寸标注）
- 审查 = Step8（审查闭环）

**每步留痕**：`preview.png`（真图快照）+ `result.json`（结构化数据）+ **该步版本 SLDDRW 副本**（`step7_skeleton.slddrw` / `step5_table.slddrw` / `step6_table.slddrw` / `step4_final.slddrw`）。

**角色分工**：规则引擎 = 骨架（稳定可测）；SW = 绘图员（画一切）；AI = 总工+质检（判断）；人 = 终审。

**AI 双职责（本期落地，非二期）**：
1. **Step4 尺寸筛选决策**：709 个模型尺寸 → AI 判断哪些放/哪些不放（多模态：看视图快照+读结构数据）
2. **每步末尾 AI 质检**：看真图快照+结构化数据 → 判定"自动放行"或"暂停待人工"

## 3. 各步改造方案

| 步骤 | 现状 | 改造后 | 复用资产 |
|------|------|--------|----------|
| Step1 | COM 加载模型 | **不变** | 全部 |
| Step2 | COM 取材料/质量/BOM 数据 | **不变** | 全部 |
| Step3 | SW导出DXF→ezdxf拆线 | **重写**：`CreateDrawViewFromModelView3` 插真实视图，SetDisplayMode3 控制隐藏线；布局引擎（比例试算/图幅升级/第一角摆位）保留改为计算 SW 视图 Position | 布局引擎、sw_drawing COM 通道、迭代重定位机制 |
| Step4 | 三线假标注 | **重写**：`InsertModelAnnotations3` 导入模型尺寸 → 规则筛 → **AI 筛** → 多余的删除/隐藏；保守放置策略保留（确定的放，拿不准的进清单）；产出真 DIMENSION 对象 | 保守放置策略、冲突检测、待人工清单机制 |
| Step5 | 自绘表格 | **重写**：`View.InsertBomTable4` 原生 BOM + `InsertBomBalloon2` 序号球标；聚合/外购识别逻辑用于校验 BOM 内容 | BOM 聚合/排序/外购识别数据逻辑 |
| Step6 | 模板文本→TEXT | **小改**：`InsertNote` 真注释对象；模板系统不变 | 全部模板 |
| Step7 | ezdxf 拼装 DXF | **重写**：基于企业图纸模板建图纸（.drwdot），标题栏走 `$PRPSHEET` 属性链接；**存骨架版 `step7_skeleton.slddrw`** | 坐标落图计算、配置体系 |
| 终版导出 | — | Step4 完成后 SaveAs `step4_final.slddrw` → 导出 DWG / PDF（原 Step7 职责收窄，终版导出后移至标注完成） | — |
| Step8 | ODA 转 DWG | **简化**：SW 另存 DWG 为主，ODA 仅作无 SW 环境兜底 | ODA 服务 |

**执行器接口签名不变、检查点纪律不变、pipeline 状态机不变。**

## 4. AI 质检守门员机制（核心新增）

每步执行完 → **留痕三件套** → AI 质检 → 三态判定：

```
Step N 完成
  ├─ 留存：output/step_N/preview.png（SW 真图快照）
  │        output/step_N/result.json（结构化数据，现成）
  │        output/step_N/step{N}_xxx.slddrw（该步版本 SLDDRW 副本）
  ▼
AI 质检（多模态：preview.png + result.json + 该步版本 SLDDRW + 该步规则红线）
  ├─ PASS：自动放行 → Step N+1（批量任务全程无感）
  └─ NEED_HUMAN：暂停流水线，前端弹处理卡片
       （问题描述 + 真图快照 + 待处理清单 + 操作建议）
       人处理完点"继续" → 局部重跑该步或放行
```

**AI 质检规则示例**：
- Step3：视图是否都在图幅内？比例是否离谱？有无视图重叠？
- Step4：标注密度是否超标？清单项数是否异常（>阈值提示人工决策）？
- Step5：BOM 表是否超图幅？行数与组件数是否一致？
- 红线类（检查点损坏、COM 失败）不走 AI，直接按现有异常体系报错。

**成本**：每步 1 次多模态调用，单图全流程 ≤10 次，成本几分钱级。

## 5. 前端：步骤回放 + 人工处理工作台

维持 Vanilla JS + ES Module（**取消 M3 Vue3 重写计划**），新增：

1. **阶段产物页（唯一主视图）**：按五阶段分组（导入/骨架/表格/标注/审查）展示产物，每阶段卡内嵌「步骤明细」折叠区（快照/耗时/警告/该步版本产物下载）
   - **前端不显示 "Step N" 编号**，只显示中文步骤名：模型加载 / 几何解析 / 视图投影 / 图纸收尾 / BOM生成 / 技术要求 / 尺寸标注 / 审查闭环
   - 用途一：AI 拦下时人工处理的界面（勾选式协同：Step4 清单逐项"放上/不放"）
   - 用途二：事后溯源分析（批量任务出问题，翻快照定责在哪步）
2. **断点控制**：AI 判定 NEED_HUMAN 自动暂停；用户处理完点"继续"
3. **终图页**：整图 PNG 大图 + SLDDRW/DWG/PDF 下载 + "在 SW 中打开"

**快照不阻断流水线**：AI PASS 的步骤快照静默落盘仅作留痕。
