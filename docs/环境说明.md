# 开发与验证环境

## 共同原则

- 两台机器使用同一 Git 仓库和分支策略；代码、测试、文档与协作规则通过 Git 同步。
- `.env`、`.venv/`、`uploads/`、`output/`、`temp/`、日志和真实运行产物留在本机，不提交。
- `.env.example` 仅提供变量名。复制为本机 `.env` 后填入密钥和路径。
- 切换机器或工具前，更新 `docs/当前状态.md` 与 `docs/交接记录.md`，再提交可交接改动。

## Mac：日常开发

适用：前端、后端、规则、DXF 相关能力、文档、代码审查，以及不依赖 Windows COM 的测试。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests/ -v
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

当前限制：生成链部分模块在导入时需要 `pywin32`，因此完整测试收集不能在 Mac 上保证可用。遇到该问题时记录为环境限制，不安装或伪造 Windows COM；将兼容性修复作为独立开发任务。

## Windows：真实 SolidWorks 验证

前置条件：Python、SolidWorks 2025、可访问的 LB26 样本与所需的 ODA File Converter（如要转换 DWG/DXF）。

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-windows.txt
.\.venv\Scripts\python -m pytest tests\ -v
.\.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

在 Windows 本机 `.env` 中设置 `ODA_PATH`、`SW_ENTERPRISE_TEMPLATE`、`SW_DRAWING_TEMPLATE` 等绝对路径。真实操作仅写入 `output/` 或 `temp/`，不得覆盖 `LB26拉臂装置/`。

## 真机验收记录

每次真机验证需在 `docs/当前状态.md` 和 `docs/交接记录.md` 中记录：SolidWorks 版本、输入样本、执行步骤、输出目录、通过/失败结论、截图或人工目视结论，以及待修复问题。
