## 二、严重问题（强烈建议修复）

### S1. step3_view_project.py 中 sw_drawing 模块延迟导入，存在运行时失败风险
- **文件**: `app\generators\steps\step3_view_project.py`
- **行号**: 278
- **问题描述**: 
  ```python
  from app.generators import sw_drawing  # 延迟导入，无 SW 环境可加载本模块
  ```
  模块级延迟导入在 asyncio 执行器回调中可能发生竞态，且缺乏 `sw_drawing` 不存在的回退处理。
- **理由**: 虽然 "无 SW 环境可加载本模块" 意图良好，但 `sw_drawing` 是 Step3 唯一引擎，缺失时应立即失败。延迟导入会掩盖导入错误，导致运行时异常信息不明确。
- **修复建议**: 将 `sw_drawing` 提到模块顶部导入，或在 `__call__` 开头显式检查模块可用性，缺失时抛 `GEN_SW_NOT_AVAILABLE`。

### S2. step4_dimension.py 标注偏移量硬编码为 10mm，未考虑视图比例缩放
- **文件**: `app\generators\steps\step4_dimension.py`
- **行号**: 47, 191, 192
- **问题描述**: 
  ```python
  _DEFAULT_OFFSET = 10.0  # 模块级常量
  dim_y = bb["min_y"] - offset  # 视图局部坐标系（实际尺寸 mm）
  ```
  标注偏移量使用视图局部坐标系的固定值（默认 10mm）。当比例为 1:100 时，图纸空间偏移仅 0.1mm，可能导致标注线压到视图实体。
- **理由**: 04-二维生成可视化模块.md 第 3.1 节明确标注位置是"视图局部坐标"，但 Step7 落图变换为 `图纸坐标 = view_position + position × scale_factor`。若 `position` 中偏移量不随比例调整，小比例图纸会出现标注拥挤。
- **修复建议**: 标注偏移量应基于图纸空间目标值（如 10mm）反算到视图局部坐标：`offset_local = offset_sheet / scale_factor`，或在 Step7 中增加标注位置的后处理补偿。

### S3. pipeline.py 进度回调异常吞没
- **文件**: `app\generators\pipeline.py`
- **行号**: 76-82
- **问题描述**: 
  ```python
  async def _emit_progress(self, task_id: str, event: Dict[str, Any]):
      if self._progress_callback is None:
          return
      try:
          await self._progress_callback(task_id, event)
      except Exception as e:
          logger.warning(f"[Task:{task_id}] Progress callback error: {e}")  # 异常被吞没
  ```
  进度回调异常仅记录 warning，不中断流水线。若前端 WebSocket 连接持续失败，用户将看到"进行中"但实际卡死。
- **理由**: 对于生成任务，进度推送是用户体验核心。回调连续失败（如前端离线）应视为异常状态，至少应记录 error 级别日志，考虑累计失败次数后主动终止或降级。
- **修复建议**: 增加连续失败计数，达到阈值（如 3 次）时记录 error 并考虑设置任务状态为 WARNING 或终止。

## 三、建议级问题（优化建议）

### J1. step2_geometry_parse.py 全局变量 `_sw_typelib` 存在并发风险
- **文件**: `app\generators\steps\step2_geometry_parse.py`
- **行号**: 34
- **问题描述**: 全局变量 `_sw_typelib` 用于缓存 COM 类型库，但 SW COM 调用已串行化（单线程执行器），风险较低。若未来改为多线程需重新考虑。
- **理由**: 当前实现安全，但耦合了"单线程执行器"假设。建议添加注释说明此耦合关系。
- **修复建议**: 添加代码注释：`# Note: _sw_typelib 缓存假设所有 COM 调用串行化于 sw_com._sw_executor 单线程`。

### J2. step3_view_project.py `_compute_scale_denominator` 在图幅升级后不重新计算比例
- **文件**: `app\generators\steps\step3_view_project.py`
- **行号**: 140-160
- **问题描述**: 代码已实现图幅升级后重新计算比例（行 201-205），但 `_compute_scale_denominator` 的 docstring 和注释仍提到"超出 1:100 仍装不下 → 截断并 warning"，与 08-01 修正后的图幅升级逻辑不一致。
- **理由**: 文档/注释与代码实现已不同步。当前实现会先尝试 A3 比例，图幅升级后重新计算，而非简单截断。
- **修复建议**: 更新函数 docstring，准确描述"先按基准图幅试算比例，图幅升级后若比例可放宽则重算"的逻辑。

### J3. step4_dimension.py 标注冲突检测仅覆盖同朝向标注
- **文件**: `app\generators\steps\step4_dimension.py`
- **行号**: 256-280
- **问题描述**: `detect_overlaps` 函数仅检测同朝向（水平/垂直）标注线的共线重叠，直径/半径标注（斜向）仅参与简化检测。
- **理由**: 保守放置策略下 `detect_overlaps` 仅用于校验已放置标注（预期无重叠），当前简化逻辑可接受。但契约字段 `overlaps` 可能给人"完备检测"的错觉。
- **修复建议**: 在 `overlaps` 字段文档中说明检测范围（仅同朝向共线），或考虑增加斜向标注的包围盒相交检测。

### J4. pipeline.py 步骤超时后无清理机制
- **文件**: `app\generators\pipeline.py`
- **行号**: 265-271
- **问题描述**: 
  ```python
  except asyncio.TimeoutError:
      step_result.status = StepStatus.ERROR
      step_result.error = f"Step timeout after {step_config.timeout_seconds}s"
  ```
  步骤超时仅标记失败，不清理可能仍在运行的执行器任务（如卡死的 COM 调用）。
- **理由**: SW COM 调用无法强制终止（pywin32 限制），但应至少记录警告，提示"后台 COM 调用可能仍在运行"。
- **修复建议**: 超时处理中增加日志警告，提示用户可能需要手动检查/重启 SW 进程。

### J5. placeholders.py 中 Step3 占位执行器与实际执行器类名冲突
- **文件**: `app\generators\steps\placeholders.py`
- **行号**: 48-49

  class ViewProjectExecutor(PlaceholderExecutor):

      step_name = StepName.VIEW_PROJECT

  占位执行器与实际执行器同名，依赖导入顺序决定使用哪个。

- **修复建议**: 占位执行器重命名为 `ViewProjectPlaceholder`，或删除已替换的占位类（Step3/4 已完成替换）。

### J6. step1_sw_load.py 与 step2_geometry_parse.py 存在重复 COM 初始化代码
