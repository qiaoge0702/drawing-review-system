## 【建议级】

### S1. 第一角投影轴向符号约定缺失，且无镜像检测测试（正确性）
- **位置**: step3_view_project.py:32-36（`_VIEW_DEFS` axes 定义）
- **问题**: 三视图轴向映射只取了分量索引 `(u,v)`，**未定义符号翻转**。第一角法下俯视图向图纸旋转 90° 后 v 轴对应 -Y、左视图 u 轴存在 ±Y 约定问题。当前实现对对称几何（盒体/圆柱）投影结果自洽，但对非对称零件，俯/左视图可能呈镜像且**现有测试全部使用对称几何（box/cylinder），永远无法暴露镜像错误**。bounding_box 断言对镜像天然不敏感。
- **建议修法**: ① 在 `_VIEW_DEFS` 注释或 doc 04 明确记录每视图 u/v 轴与 SW 坐标系的符号约定（哪怕是"M2 暂取正方向，Step7 DXF 落图时统一翻转"的显式决策）；② 增加一个非对称几何测试（如 L 形/带单侧凸台 mesh），断言投影轮廓中可区分镜像的特征点坐标。

### S2. `views=[]` 被静默吞为默认值——升级为建议级（异常处理）
- **位置**: step3_view_project.py:146 `ctx.parameters.get("views") or ["front", "top", "left"]`
- **问题**: 与 tester 报告一致，但**我不同意"提示级"分级**。SOUL 异常处理维度明确："失败静默返回默认值（与真空值不可区分）"。调用方显式传空列表（上游 views 配置解析 bug 的典型形态）会被静默改成三视图，产出一个看似成功但非调用方意图的 views.json，下游 Step7 将基于错误输入继续执行——这正是本维度要防的模式。
- **建议修法**: `view_names = ctx.parameters.get("views"); view_names = ["front","top","left"] if view_names is None else view_names`，随后 `if not view_names: raise SWException(..., GEN_INVALID_FILE 或 GEN_UNSUPPORTED_FEATURE)`。

### S3. 输出契约缺 `section_hatch` 键，layout 坐标系关系未定义（契约符合）
- **位置**: step3_view_project.py:113-125（project_mesh 返回体）、`_build_layout`
- **问题**: ① doc 04 第二节 view 对象含 `section_hatch` 字段，实现完全省略（hidden_lines/center_lines 以空数组占位但 section_hatch 连键都没有），下游若按 doc 逐键消费会 KeyError——同为预留字段，处理不一致。② layout.view_positions 给出图纸坐标 (x,y)，但 entities 坐标是 **mesh 局部坐标（可为负）**，二者间的平移关系（pos - bounding_box.min）契约未写明，Step7 渲染器只能自行猜测。
- **建议修法**: ① view 对象补 `"section_hatch": None` 占位；② 在模块 docstring 或 doc 04 补一句"实体坐标为视图局部坐标，落图时按 view_positions[name] - bounding_box.min 平移"。

## 【提示级】

### T1. `project_mesh` 非法 view_name 抛裸 KeyError（:81）
与 tester 报告一致，同意低级。executor 入口已预校验（:147-153），仅直接调用该函数可达。建议函数内 `_VIEW_DEFS.get(view_name)` 校验并抛 SWException(GEN_UNSUPPORTED_FEATURE)，与 executor 行为对齐。不升级：生产路径不可达。

### T2. dev 测试 STEP 时代残留
与 tester 报告一致。test_step3_view_project.py:5-7 模块 docstring 及 :39 `fake_run_sw` 内 `Path(step_path).write_text("ISO-10303-21;")` 写的是 STEP 占位内容而变量名/语义已是 STL，:33 fixture docstring 亦提 "STEP 加载"。M2 收口时随注释清理。

### T3. STL 加载失败路径缺 logger.exception（:191-200）
导出失败路径有 `logger.exception`（:171），trimesh 加载失败路径直接重包 SWException 无日志，排查时丢 traceback。补一行即可。

### T4. 重几何计算在事件循环线程执行（健壮性，存疑）
`trimesh.load` + 逐面片 shapely union 在 async 函数内同步执行。当前全局串行 worker（SW COM 单线程约束）下无实际竞争，但大装配 STL 会阻塞事件循环、延迟 WS 进度推送。M2 可接受，若后续放开并发需挪入 `run_in_executor`。标注存疑、不升级。

### T5. `_build_layout` 魔法数字
换行阈值 400.0 / 间距 40.0 / 起始 20.0 硬编码，A3 横向实际宽 420mm，且 sheet_size 硬编码 "A3"（doc 示例为 A1）。M2 占位可接受，建议提为模块常量并注明单位 mm。

### T6. SaveAs3 未检查返回值/未用 Silent 选项（:55）
`SaveAs3` 返回 (bool, errors, warnings)，当前仅靠事后文件存在性兜底；Options=0 可能弹 SW 对话框阻塞 COM 线程。已有存在性检查兜底故不升级，建议 Options 传 `swSaveAsOptions_Silent`(1)。
