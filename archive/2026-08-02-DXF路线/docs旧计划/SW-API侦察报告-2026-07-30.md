# SW API 技术侦察可行性报告

**日期**: 2026-07-30 | **侦察人**: 财神 | **样本**: LB26.10000底架.SLDASM + LB26.11202轴套.SLDPRT
**环境**: SolidWorks 2025 正式版（COM 33.3.0 实测连接）

---

## 一、结论（先说答案）

**SW API 路线可行，且比原设计更优**：不需要自己写投影引擎，**直接用 SW 工程图视图作为投影引擎**，读取视图实体得到带真实几何参数（真圆/真线）的 2D 数据。全链路已实测跑通。

## 二、验证结果矩阵

| 能力 | 状态 | 实测证据 |
|------|------|----------|
| 装配体打开+组件遍历 | ✅ | 底架 119 组件，轻化组件可解析（ResolveAllLightWeightComponents） |
| Face 级 tessellation | ✅ | 轴套 9 面/1420 三角形（备用方案保底） |
| Body 级 GetTessellation | ❌ | COM 服务器错误（放弃，有替代） |
| Edge 曲线类型识别 | ✅ | LINE/CIRCLE/INTERSECTION 分布清晰（`curve.Identity` 属性非方法） |
| 真圆参数 | ✅ | CircleParams 圆心+半径+轴向（垫板 R=5mm 实测正确） |
| **工程图视图创建** | ✅ | gb_a3 国标模板 + `*前视`（中文版视图名必须中文！） |
| **视图实体读取** | ✅ | `GetVisibleEntities2(comp, 1)` 取到 silhouette 边 COM 对象 |
| **3D→2D 变换** | ✅ | ModelToViewTransform 16 维矩阵手动应用（MultiplyTransform 在 pywin32 下不可用，手算矩阵绕过） |
| 端到端提取 | ✅ | 轴套前视图提取 4 个真圆，坐标+半径全对 |

## 三、推荐架构（替代原"自写投影"设计）

```
SW 模型 → 新建工程图(gb_a3模板) → 插入预定义视图(*前视/*俯视/*左视)
        → ForceRebuild3 → GetVisibleEntities2 读取视图实体
        → 每实体: curve.Identity 判别类型 → LineParams/CircleParams 取真实参数
        → ModelToViewTransform 手动矩阵 → 2D 图纸坐标
        → 契约 JSON（views.json，与现契约完全兼容）
```

**对比自写投影的优势**：SW 自己算轮廓/遮挡（HLR 内核），我们不做投影数学，只做数据搬运和格式化。工作量从"写引擎"降为"写读取器"。

## 四、遗留未知项（诚实清单）

| 未知项 | 影响 | 对策 |
|--------|------|------|
| 隐藏线数据提取 | 隐藏线可能需另设视图显示模式后重读，或 SW 不直接给 | ② 阶段先试 `GetVisibleEntities2` 其他类型码 + 视图显示模式切换；实在不行用 tessellation 自算（备用路径已验证） |
| INTERSECTION 类型边（样条/交线） | 焊接件常见 | 采样离散为折线（GetCurveParams3 + Evaluate），精度可控 |
| 装配体视图（焊合图是装配视图） | 多组件实体的组件归属 | GetVisibleComponents 已能枚举，逐组件读取即可 |
| 中文版 API 名词 | 视图名/特征名全中文 | 已确认 `*前视`，其余在 ② 阶段建常量表 |
| 性能 | 119 组件装配整图耗时未测 | ② 阶段实测，超时可分组件处理 |
